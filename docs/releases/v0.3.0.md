# Stow v0.3.0

S3-shaped storage for development, agents and controlled private deployments,
with native filesystem storage and a browser WASM runtime.

## Distribution

This release provides native downloads on GitHub for Linux and macOS, on x86_64
and ARM64. Each archive contains `stow-s3`, the license and the README.
Verify the downloaded archive against `SHA256SUMS.txt` from the same release.

npm and PyPI publication are deferred. TypeScript and Python clients remain
available from source; this release does not claim registry installation works.
Executed live AWS S3, Cloudflare R2 and custom-provider receipts are not part of
this downloads-only release. The local conformance and artifact-consumer gates
still run before publication.

## Changes

- Native workspaces support preparation, immutable checkpoints, portable handoff,
  adoption, guarded saves and recovery of interrupted save requests.
- Browser storage supports file history, atomic project revisions, IndexedDB
  persistence, workers and bounded object streams through the binary WASM bridge.
- Filesystem objects use protobuf metadata and raw payloads. Header-only listing,
  incremental managed usage accounting and streaming reads avoid full-payload
  decoding during metadata and quota operations.
- Ordinary unbound filesystem uploads stage outside the runtime publication lock;
  uploads and copies use bounded payload scratch while retaining atomic publication.
- Independent reads overlap safely and return caller-owned bytes. Internally owned
  HTTP bodies avoid redundant copying without changing caller ownership rules.
- The embedded implementation is isolated behind the existing public Go facade,
  reducing the packaged WASM runtime. Browser hosts use streaming instantiation
  where supported, and reuse stream buffers after copying bytes into JavaScript.
- Native workspace indexes use compact encoding, with unchanged fields and format
  version. Each index update still replaces the complete index.

## Filesystem upgrade compatibility

Existing version-1 JSON object records remain readable. Opening a directory does
not rewrite its objects. New or overwritten objects use version-2 records with
protobuf metadata and raw payloads; mixed directories are supported.

**Older Stow versions cannot read version-2 records.** Preserve a backup before
upgrading persistent object-record directories if you need a downgrade path.
This change applies to object-record storage, not the editable workspace layout.
The S3 HTTP protocol and journal JSON formats are unchanged.

Guarded and capacity-bound writes retain their existing admission and recovery
paths. Windows retains its existing captured-payload materialization; native
workspace support remains limited to Linux and macOS.

## Installation

Download the matching `stow-linux-amd64.tar.gz`, `stow-linux-arm64.tar.gz`,
`stow-darwin-amd64.tar.gz` or `stow-darwin-arm64.tar.gz` from this release.
Extract it, put `stow-s3` on your PATH and check `stow-s3 --version`.

```sh
stow-s3 serve --port 0 --backend filesystem --data-dir .stow
```

Read the `STOW_READY` record for the endpoint and generated credentials, then
connect with an S3 SDK using path-style addressing and region `us-east-1`.
