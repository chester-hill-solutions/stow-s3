# Stow v0.3.4

This patch release corrects authentication and conditional-request behavior,
fixes MCP plugin packaging, and updates dependencies. It includes the changes
since the published v0.3.3 release, not only the latest dependency updates.

## Distribution

Native GitHub downloads target Linux and macOS on x86_64 and ARM64. Verify each
archive against this release's `SHA256SUMS.txt`. npm and PyPI publication remain
deferred; use a source checkout for the TypeScript and Python clients.

## Correctness fixes

- Authenticate every value of a signed HTTP header. Valid repeated-header
  signatures are accepted; adding, changing or removing a signed value requires
  a new signature. This closes the repeated-header issue documented in v0.3.3.
- Compare entity tags exactly, including case, for read, write and COPY
  conditions. A case-changed tag identifies a different representation. Wildcard
  and weak-validator behavior remains supported. This closes v0.3.3's opaque
  ETag comparison issue; tag generation and stored identities do not change.
- Order SigV4 query parameters after URI encoding, including encoded values
  within repeated names. Requests with encoded query names now agree with the
  pinned Node signer. This closes v0.3.3's encoded query-name ordering issue.
- Copy MCP plugin template children into the new output directory, so newer
  Node versions do not reject copying onto an existing destination. Existing
  output directories are still refused.
- Require the intended precondition failure in the JavaScript and Python
  conditional-write examples, and verify that the stored content is retained.

## Dependencies and tooling

- Update the Go and JavaScript AWS SDK dependencies and keep the benchmark
  module aligned. CI now compiles the benchmark tests to catch dependency drift.
- Update Playwright, Node type definitions, globals, ESLint, typescript-eslint,
  Marked and pinned GitHub Actions used by the existing workflows.
- Update the MCP extension to esbuild 0.28.2 and native TypeScript 7.0.2. Declare
  its verified CSS export precisely; strict side-effect import checking stays
  enabled. Tests reject missing imports and nonexistent CSS exports, verify CSS
  bundling, and keep shared ESLint on the core package's compiler API.
- Refresh installation guidance and scoped benchmark documentation. Historical
  measurements retain their original build identities and workload limits; they
  do not establish new release-wide performance results.

## Compatibility and limits

There is no new storage format or public API migration in this patch. Clients
must return opaque ETags with their original case. The existing filesystem
record-v2 and outbox schema-4 downgrade restrictions from v0.3.3 still apply.

Go remains pinned to 1.25.6, and the core TypeScript compiler remains unchanged.
The held scanner update, Go 1.26 memory-contract migration and wider core
TypeScript 7 migration are excluded.

This release makes no executed-live-provider or general crash-recovery claim.
The default browser suite leaves the 1 GiB workload and direct Railway
qualification as explicit opt-in checks.
