# Stow v0.3.5

This release adds MCP over HTTP, guarded memory saves through WASM, delimiter
listings and classic S3 ListObjects. It also fixes storage refusals, readiness
descriptor ownership and Git preparation races.

## Distribution

Native GitHub downloads cover Linux and macOS on x86_64 and ARM64.
Verify each archive against `SHA256SUMS.txt`.

The TypeScript client and all four native carriers are now published on public npmjs:

```sh
npm install @chester-hill-solutions/stow-s3@0.3.5
```

The separately authorized interactive bootstrap published the exact rehearsed artifacts.
All five registry checksums and anonymous exact-version installations were verified.
See the [publication record](../development/npm-publishing.md#published-035) for source and verification details.

PyPI publication remains disabled. Use a source checkout for the Python client.
Future automated registry publication and trusted publishing remain disabled.
Live-provider compatibility remains unverified under the existing first-npm-release waiver.

## New capabilities

- Serve the existing MCP tools through sessionless streamable HTTP with
  `stow-s3 mcp --http-addr host:port`. Stdio remains the default. Remote HTTP
  requires explicit consent and a separate MCP bearer token.
- Expose `readForSave`, `saveObject`, `resolveSave` and `releaseObservation` through
  the synchronous and asynchronous WASM/TypeScript APIs. Observation tokens stay
  bound to their runtime and resource, with bounded retention and expiry.
- Report the underlying guarded-save, durable-request and recovery-hold
  capability flags accurately. The qualified memory runtime supports guarded
  comparison but does not retain durable request receipts. Request-key saves and
  resolution remain unsupported there.
- Carry listing delimiters and `commonPrefixes` through the embedded runtime,
  WASM bridge, content hosts and TypeScript APIs. Objects and prefix groups share
  the page limit. Go and JavaScript use the same UTF-8 ordering and cursor rules.
- Answer classic S3 ListObjects requests with V1 XML and marker pagination.
  Delimiter listings return `NextMarker` when truncated; flat listings resume
  after the last key. V2 behavior and unsupported-subresource refusals remain
  explicit in the [compatibility contract](../contracts/compat-contract.md).

## Remote listener migration

A native S3 bind beyond loopback now requires `--allow-insecure-remote`,
provisioned S3 credentials and a usable admin token before listening. Loopback
defaults remain available. The TypeScript launcher forwards the same consent and
provisions its admin token through the child environment.

Remote MCP uses `--mcp-token` or `STOW_MCP_TOKEN`, separate from the admin token.
Terminate TLS externally. See [native serving](../running-and-probing.md#serving-beyond-loopback)
and [MCP HTTP](../contracts/object-mcp-contract.md#serving-the-surface-over-http).

## Correctness fixes

- Map known multipart, permission and capacity refusals to the appropriate
  404, 403 or 507 responses while retaining deliberate corruption errors.
- Validate caller-supplied multipart upload IDs before constructing paths in
  either path-backed store. Preserve pending-save refusal precedence.
- Keep multipart-upload limits aligned across the Go readiness writer and both
  clients, with protocol and capability parity checks.
- Write readiness records through an owned duplicate so garbage collection
  cannot close the caller's original descriptor or a later file reusing it.
- Disable automatic maintenance on owned Git seed fetches so metadata admission
  does not race a disappearing maintenance lock. Quotas and checkout checks
  remain enforced.
- Select the pinned Go installation for coverage and its nested tool invocations.
- Report effective upstream-write authorization accurately when consent exists
  but a narrower authority grant still refuses propagation.

## Performance and tooling

- Derive reversible filesystem keys before pagination and defer object-header
  reads to returned rows. Listings still walk the object tree and sort candidates.
- Reuse verified unchanged parent checkpoint payloads through hard links when
  possible, with verified copying as the fallback. Retention still charges full
  logical size. Stored checkpoint files require the existing same-user trust;
  restore and export continue to verify digests.
- Add opt-in checkpoint phase diagnostics. Dated workload reports describe
  their own measurements and do not establish release-wide performance claims.
- Update AWS SDK dependencies, Node definitions and the duplication scanner.
  Keep the existing quality gates and record the reduced Go comment budget.
- Move site deployment to pinned cf/Wrangler configuration with an explicit
  assets build. Site tooling requires Node 22.18 or newer; the SDK remains
  compatible with Node 20.
- Reconcile architecture and storage documentation while preserving dated
  historical evidence and unresolved contract decisions.

## Compatibility and qualification limits

No storage-format migration is introduced. Existing filesystem record-v2 and
outbox schema-4 downgrade restrictions still apply. Go remains pinned to 1.25.6;
the core TypeScript compiler and WASM memory thresholds remain unchanged.

For source development, use current `main`. The original v0.3.5 tag predates the
native-package lock metadata refresh and can fail `npm ci` after the first npm publication.
The published npm package and native downloads are unaffected.

This release makes no executed-live-provider or general crash-recovery claim.
Host-backed guarded saves, durable memory retries and resource ACLs are not
qualified by the new memory save API. Browser 1 GiB workloads and direct Railway
qualification remain opt-in checks.
