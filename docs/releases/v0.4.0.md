# Stow v0.4.0 candidate (unreleased)

> This is a release candidate record, not a release announcement. Version 0.4.0
> is not published to npm or PyPI, and no GitHub release or native download is
> available yet. Keep using the public v0.3.7 instructions until a release is
> announced.

## What changes

- Add opt-in MCP workspace file resources for live directories, paged directory
  listings and bounded file reads.
- Add opt-in resources for a host-selected saved checkpoint, including bounded
  directory and byte-range reads.
- Add opt-in native workspace editing tools for reading a file before a save,
  submitting an idempotent save request and resolving its receipt.
- Add durable file-save recovery records and checkpoint barriers that refuse
  capture or cleanup while a save is unresolved.
- Add workspace browser support and documentation for the opt-in profiles.

The existing object-server profile and default MCP startup remain unchanged.
These features do not claim to sandbox other host processes or control their
network access.

## Choose an MCP profile

- [Workspace file resources](../guides/workspace-resources.md): browse allowed
  directories and read current working files without a file-writing tool.
- [Checkpoint file resources](../guides/checkpoint-resources.md): read one
  host-selected saved view, including verified ranges, after live files change.
- [Managed file saves](../guides/workspace-file-saves.md): compare against an
  observation, retain a save receipt and resolve an interrupted reply.

These profiles require a prepared, registered workspace and a source-built
candidate binary. File reads are scoped and bounded. Managed editing writes
whole files up to 64 KiB; the host must keep other writers quiescent. It does
not add shell execution, directory mutations or general collaborative editing.
A file save and a checkpoint capture remain separate operations.

## Distribution and qualification

The Go binary, npm package and four carrier manifests, and Python metadata are
synchronized at 0.4.0. Public native and npm installs remain at 0.3.7 until
publication; Python remains available from source. The existing object-store
format and upgrade restrictions continue to apply.

Native qualification at commit `3868daaa0af4874d01ff9def72d5f092ca2a093b` passed:

- [All 14 CI jobs](https://github.com/chester-hill-solutions/stow-s3/actions/runs/43615538452):
  Go/race tests, conformance, Node 20/22/24, Python, WASM, browser tests and standards.
- [The release rehearsal](https://github.com/chester-hill-solutions/stow-s3/actions/runs/43615532772):
  four native builds and wheel consumers, four installed npm/MCP consumers and
  archive checksums, on Linux and macOS with x64 and ARM64.
- Installed consumers browsed resource-only working files, committed and resolved
  a managed save, then read immutable checkpoint bytes after live files changed.

Revision-bound results for subsequent documentation updates and artifact
identities are tracked in
[release candidate PR #139](https://github.com/chester-hill-solutions/stow-s3/pull/139).
Named external consumer hosts and model-provider behavior require separate
evidence; a platform smoke does not establish those claims. Windows workspace
support and protected cross-host adoption are not qualified by this release.

Automated npm publication, npm trusted publishing and PyPI publication remain
disabled. A successful rehearsal publishes no GitHub release or registry package.
