# Stow v0.4.1

The v0.4.1 patch fixes policy handling for receipt-backed workspace checkpoint
modes. Native downloads are listed on the [v0.4.1 GitHub release](https://github.com/chester-hill-solutions/stow-s3/releases/tag/v0.4.1);
verify each archive against its [SHA256SUMS.txt](https://github.com/chester-hill-solutions/stow-s3/releases/download/v0.4.1/SHA256SUMS.txt).
Public npm packages remain at v0.3.7; Python remains source-only and is not
published to PyPI.

## What changes

- Refuse `workspace checkpoint --policy` when combined with `--request-key` or
  `--resolve`. Those receipt-backed modes have no policy-aware contract. The
  refusal occurs before receipt lookup, reconciliation or capture.
- Qualify direct policy-checked capture against persisted policy replacement,
  expiry, damage and removal. Replacements are observed at the next admission;
  missing, damaged and expired records remain unknown-policy errors rather than
  grants.
- Add ordinary-SDK download continuation conformance across retained filesystem,
  runtime-filesystem and workspace backends, including restart, range validators,
  exact bytes and refusal when the remote object is missing or changed. This is
  conformance coverage for the existing example, not a shipped transfer API.

The download coverage qualifies the existing resumable-transfer example; it adds
no new transfer SDK or portable unfinished-transfer state. The v0.4.0 workspace
resources, managed saves and checkpoint reads remain the features introduced in
[v0.4.0](v0.4.0.md).

## Compatibility and limits

Published v0.4.0 silently ignored `--policy` when receipt-backed capture or
resolution arguments were also present. On that release, use direct capture for
policy enforcement and do not combine policy flags with request keys or resolve.
The v0.4.1 CLI refuses those combinations. Existing unscoped keyed capture and
receipt behavior remains available.

Policy-checked direct capture is a local CLI profile using the local
administrator's authority and a file-backed policy. It does not add policy-aware
receipt APIs, protected-host support, multi-tenant authorization, an OS sandbox,
or cancellation of a capture after admission. Existing workspace compatibility,
retention, writer-quiescence and plaintext boundaries continue to apply.

## Distribution

The standalone native downloads and Go module use version 0.4.1. npm remains at
0.3.7, including its packaged native binaries. Python remains available from a
source checkout; PyPI and automated npm/PyPI publication are disabled.
