# Stow v0.4.3

This release settles a workspace file-save journal instead of locking the
workspace behind it, adds a persistence adapter contract with browser and
filesystem implementations, accepts the CRC64NVME multipart checksums AWS
clients send by default, and makes the agent-facing surfaces installable and
measured. No storage-format migration is required.

## Release state

Prepared in this tree on 2026-11-20. The v0.4.3 tag, native binaries and any
registry publication are produced by the authorized release step; until that
step runs, v0.4.2 remains the current native release and npm publishes 0.3.7.

## Changes since v0.4.2

### Workspaces

- A settled workspace file-save journal no longer blocks its workspace. Opening
  classifies the journal the way the save barrier already did — matching
  identity and no pending record — so `workspace resume`, `workspace serve` and
  `workspace destroy` work after an MCP editing session, and a second editing
  session adopts the journal it finds. A pending or unverifiable journal still
  refuses every one of those surfaces and is resolved with
  `mcp --workspace-edit --recover-file-saves`. ADR 0022 records the decision.
- Workspace editing accepts `--max-file-bytes`, raising the whole-file bound
  from 64 KiB to at most 1 MiB (1048576). The save, observation and response
  paths follow the configured bound, the default is unchanged, and a refusal
  still names the limit.
- Preparing a workspace skips common credential paths (`.env`, `.npmrc`, SSH
  keys and the like) and reports them in `excluded_sensitive_paths` instead of
  aborting the whole prepare. `include_sensitive_inputs: true` still copies
  them, and `sensitive_paths: "refuse"` preserves the previous refusal. Git
  inputs remove a skipped path from the checkout rather than leaving it in the
  workspace.
- Workspace editing refusals report `not_committed` and carry a
  machine-readable `next` step, so an agent is not sent into a `resolve_save`
  loop for a call that had no effect. `unknown` is reserved for an effect that
  is genuinely undetermined. Zero timestamps no longer appear as year-one
  values, and importing the same checkpoint archive twice returns the existing
  checkpoint instead of failing.

### Storage and protocol

- Multipart uploads accept CRC64NVME with full-object completion. The completion
  claim is verified against the assembled object before publication and reported
  by the complete response, `HEAD` and `GET`. Composite checksums remain
  refused. ADR 0024 records the decision.
- A streaming SigV4 request is refused by name
  (`STREAMING-AWS4-HMAC-SHA256-PAYLOAD`) with the supported alternatives,
  instead of being reported as an invalid content hash.
- Object writes carrying `Cache-Control`, `Content-Disposition`,
  `Content-Encoding`, `Content-Language` or `Expires` are refused with
  `501 NotImplemented` before any mutation. The record has no field for them, so
  accepting the write acknowledged metadata the next `HEAD` could not return.
  `Content-Type` and `x-amz-meta-*` are unchanged.
- A committed save is proven to survive `SIGKILL`: the workspace resumes, the
  bytes are intact and a checkpoint captures them.

### Persistence adapter

- Add a persistence adapter contract: five operations (get, put, list, delete,
  conditional put) that a platform can implement to supply Stow's storage, with
  `stow.OpenAdapter` bridging them to the embedded runtime. See
  [the contract](../contracts/persistence-adapter.md); ADR 0023 records the
  decision.
- The directory reference reuses the filesystem store, and
  `pkg/stow/persistence/adaptertest` is the shared pass/fail suite a new adapter
  runs.
- `IndexedDbAdapter` implements the five operations over IndexedDB and is
  exported from the browser entry, with a Playwright qualification lane.
- The S3 corpus is importable: `conformance/corpus.RunAdapter` runs every
  supported case against a host's own `persistence.Adapter`, and
  `conformance/corpus.Run` runs them against an existing S3 endpoint. A case can
  declare `requires`, and a backend that lacks a capability skips it and says so
  instead of failing or silently passing.

### Agents

- Ship a Claude Code plugin and marketplace manifest, so one install delivers
  the guidance: `claude plugin marketplace add chester-hill-solutions/stow-s3`,
  then `claude plugin install stow@chester-hill-solutions`. Both manifests pass
  `claude plugin validate --strict`.
- Add a host setup guide for Claude Code, Codex, OpenCode, Node and Python,
  including a zero-config object-mode MCP entry for each host and a first prompt
  that stores and reads a key. See the
  [host guide](../guides/agent-hosts.md).
- Add a balanced 20-case conversion eval (12 positive, 8 negative, 3 held out)
  with a host-neutral runner. Measured on 2026-11-20: every positive asks for an
  install, every negative stays silent, and the no-guidance baseline scores
  zero. See the [eval record](../reviews/2026-11-20-conversion-eval.md).
- Gate install claims against the npm publication receipt, so a documented pin
  cannot name a version that was never published.
- The native workspace editing refusals that an agent reads now say which call
  to make next, and the workspace editing bound is configurable rather than a
  fixed 64 KiB.

## Compatibility and limits

Existing filesystem record-v2 and outbox schema-4 downgrade restrictions continue
to apply. Go remains pinned to 1.25.6 and the core TypeScript compiler remains at
5.9.3. The held Go 1.26 memory-contract and core TypeScript 7 migrations are
excluded. Dependency audit findings are clear for the shipped dependency trees;
this release is not a clean security audit of every toolchain.

The persistence adapter models five operations and no multipart upload, so an
adapter backend skips the multipart corpus cases rather than emulating them. The
adapter does not change the object protocol, the storage record or the
workspace trust model.

Local qualification and packed consumers do not establish live-provider
compatibility. No executed AWS S3, Cloudflare R2 or custom-provider compatibility
claim is made. Existing workspace trust, retention, plaintext and
writer-quiescence limits remain.

## Distribution

Native archives and the Go module are distributed from tag v0.4.3. Verify native
downloads against the release's `SHA256SUMS.txt`. The npm publication for 0.4.3
remains pending; npm publishes 0.3.7. Automated npm publication and trusted
publishing remain disabled. Python remains source-only; no PyPI publication is
included.
