## Change and contracts

`capacityFileAdmission` extracts the existing projected-usage calculation from `writeCapacityFile` without changing its scans, charging or writer callback. Bound bucket creation invokes that calculation and `Namespace.WithAdmission` **before** `MkdirAll`. Its admitted callback creates the existing empty objects directory, writes the same JSON metadata atomically and syncs from the objects directory through its ancestors. The existing `ErrUnknown` preserves the projected charge if publication or its fence has an uncertain outcome. Original I/O errors remain inspectable through `errors.Is` and no committed-success marker is invented.

Deletion retains the existing object/upload emptiness checks and uses `removeCapacityPath`. Namespace admission rejects removal of held metadata before effects; a successful deletion releases the resource charge immediately and fences the parent. The unbound path keeps its existing directory and metadata behavior. Bucket validation, creation dates, empty-bucket usability, nonempty rejection and existing S3 behavior remain covered by the storage tests and conformance profiles. A pre-effect recovery-reserve refusal leaves no bucket directory, no `HeadBucket` result and no listing entry. Deleting an admitted bucket makes room for a later creation.

This does not promise rollback for a native filesystem failure after directory creation: the generic atomic writer cannot certify absence of effect on error, so reservation retention is conservative. Reopening or a subsequent operation reaching reconciliation scans actual owned files. The old-state scan may release a reservation retained after a known-no-effect I/O failure; abandoned stores may temporarily consume capacity until reconciled. Bound buckets can now return existing capacity/held/unknown errors which previously were bypassed. The existing resource-count and ledger limits still apply. S3 keeps its existing error mapping: namespace capacity/hold/unknown sentinels currently fall through to generic `InternalError` (HTTP 500), rather than a specialized capacity response. This change enforces refusal without adding an error API; callers may observe that existing generic failure where the bypass previously returned success. The four conformance profiles cover existing protocol behavior; the six native bound-store regressions cover namespace admission. No existing on-disk data is migrated.

[Fixed normal suite](2026-10-18-bucket-admission/raw/final/focused-normal.log), [fixed race suite](2026-10-18-bucket-admission/raw/final/focused-race.log): all six regressions pass twice each with no permission/root skip. The concurrent case verifies shared admission and exact subsequent scans rather than relying on goroutine ordering.
