## Change and preserved contracts

The filesystem completion passes its already-verified part buffers directly to
`atomicfile.WriteParts` through the existing private object/capacity writers.
The existing record's `payloadSize` supplies the header size. Whole-object
checksums consume the selected buffers in order through the existing digest
interface. Capacity admission hashes the identical header-plus-parts sequence and
counts its full physical length; it no longer needs a contiguous encoded copy.
Private writer arguments accept multiple slices; no public API, dependency,
format, staging abstraction, cache or index is added.

Each source file is read once through the existing `os.ReadFile` path. Publication
uses those same captured bytes, so it cannot validate one source version and then
reopen another. ETag checks, actual stored part sizes, minimum sizes, checksum
refusal, recovery holds and checksum/metadata normalization keep their ordering.
The atomic writer still creates a same-directory temporary file, writes, chmods,
syncs, closes, renames and syncs its directory. Capacity reservation precedes those
side effects, physical resource identity includes the header, uncertain effects
retain `ErrUnknown`, and committed cleanup failures retain metadata plus
`ErrMutationCommitted`. Cleanup and reopened capacity behavior remain unchanged.

Regression coverage includes allocation bounds at 8 MiB, one/two parts, both
capacity modes, reopened byte hashes and metadata, and final physical capacity.
Empty/nonempty SHA-256 completions produce usable full-record capacity dependencies.

## Costs, limits and next finding

Completion still materializes every selected part: working memory remains O(total
selected payload), with O(part count) slice descriptors. This is not a streaming
completion or a new RAM quota. The writer now issues one payload write per part
instead of one write for the concatenation. Checksums and capacity hashing process
the same bytes incrementally; digest state and slice descriptors have small fixed/
per-part costs. Shared private single-slice writers also acquire the variadic
argument representation and incremental hash path; small-object controls above
expose fixed-cost effects but do not qualify every unrelated writer workload.
No extra part reads, descriptors, files, sync stages or migrations are introduced.

The next highest-priority measured memory path is namespace-bound incoming PUT
staging: `StageObject` deliberately chooses `PreparePut` buffering, and buffered
commit can encode another full payload. The previous incoming-memory review records
about 393.5 MB stage allocations plus 67.2 MB commit allocations for a 64 MiB bound
streaming-reader input, including full staging before small-quota refusal. Those
older measurements need current-path qualification before changing that path.
The runtime multipart quota adapter also still buffers and forwards a borrowed
reader. No next fix, broader storage abstraction or indexing work is implemented.
