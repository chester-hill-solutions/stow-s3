# Local room contract

`CollaborationRoom.open({root, stateDir})` opens one coordinator for a shared directory. `stateDir` must be outside the captured workspace and is bound to its canonical root in `room.json`; reusing that directory for a different workspace is rejected. The coordinator alone publishes messages; this prototype does not support multiple coordinators or hostile writers.

Register participants with stable IDs and explicit `subscriptions`. `ownedFiles` describes their assignment; call `claim(id, paths)` to reserve files or directory prefixes before starting a writer. Claims reject overlaps and stay in memory. `release(id)` drops editing claims while keeping the participant and its listeners active, so an idle agent still receives peer reports. The runner must verify its writer is quiescent before releasing. After verifying the participant's server/process has exited, call `leave(id)` to mark it stopped, drop remaining claims and remove its listeners. Cooperative claims do not intercept filesystem edits.

Calling `register` again updates that participant's assignment and subscriptions and makes it active. Existing claims remain until release; existing publication recipients remain unchanged. Portable restoration to another root requires a fresh external `stateDir`; its durable publications replay pending reports instead of importing the previous host's acknowledgment state.

`publish({id?, from, files, summary})` stores an immutable, atomic JSON file under `collaboration/messages/`. Publications have monotonic sequence numbers and recipients frozen from active subscriptions at publication. Exact paths, directory prefixes ending `/`, and directory patterns ending `/**` match; senders never receive their own publications. Reusing a message ID returns its original publication when content matches and rejects differing content. Reports are limited to 200 paths and 16000 characters.

`listen(id, callback)` returns an unsubscribe function and invokes the callback once per pending message during that listener session. A filesystem watcher triggers reconciliation; model polling is unnecessary. `pending(id)` also reconciles the durable files. Only `acknowledge(id, messageIDs)` removes messages from the pending inbox, after atomically saving acknowledgments under `stateDir`. Reattaching a listener or restarting the coordinator may replay unacknowledged reports. A callback failure is exposed in `snapshot().errors`; runtime delivery never acknowledges automatically.

`snapshot()` returns participants, claims, publications, and per-participant pending/acknowledged message IDs. `exportState()` saves sanitized participant assignments and publications in `collaboration/state.json`; it excludes claims, process identities, credentials, listener state and acknowledgments. Portable recovery preserves publications but requires fresh registration and claims. A new external state directory replays all previously addressed publications after their recipients register; existing acknowledgments prevent replay on a local restart. Subscriptions updated later do not retroactively add recipients.

The runner controls turn boundaries, publication truth, acknowledgment timing, and checkpoint quiescence. Watcher delivery is a scheduling notification, not permission to interrupt a live writer. Call `close()` after all room operations settle to release the watcher.
